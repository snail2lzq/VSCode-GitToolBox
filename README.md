# GitToolBox for VS Code

当前已实现 Git Control 管理窗口、左侧 Commit 工具窗口、仓库概览、按文件选择提交和当前行 Inline Blame，Auto Fetch 等增强功能待后续开发。

## 开发环境

- Node.js 24 LTS（见 `.nvmrc`）
- npm
- VS Code 1.95.0 或以上
- Git（仓库展示、提交及测试需要）

```sh
nvm use
npm ci
```

在 VS Code 中打开项目，按 **F5** 启动 Extension Development Host。首次调试会自动构建并持续监听源码变化。在新窗口打开一个 Git 项目，点击左侧活动栏的 **GitToolBox** 工具箱图标，或在命令面板执行 **GitToolBox: Open GitToolBox**。修改代码后执行 **Developer: Reload Window** 加载新构建。

扩展在 VS Code 启动完成后激活，通过内置 Git 扩展发现仓库，使用本机 Git 读取行归属信息及执行文件选择提交；点击刷新会重新读取本地状态，不执行 Fetch、Pull、Push。未受信任工作区不连接 Git API、不执行 Git。虚拟工作区是否能显示仓库取决于内置 Git 扩展的支持情况。日志包含扩展状态和连接/刷新错误。

## 当前行提交提示

打开 Git 跟踪的文件，光标停留约 200ms 后，行尾直接显示 `name · date · msg`（作者、作者时间、提交说明），不显示悬停详情。总长度超过 64 个字符时截断，并以 `...` 结尾，包含省略号在内最多显示 64 个字符。时间按扩展运行环境的本地时间显示。

新增/修改但尚未提交的行显示“尚未提交”，未跟踪文件显示“未受版本控制”。未保存的插入、删除和修改也参与行归属计算，不会因行号移动而显示错误作者。切换文件、分支、提交或修改内容后会更新提示。

可通过设置 `gittoolbox.inlineBlame.enabled` 关闭，支持按工作区或文件配置。只显示当前活动编辑器的单光标行；不支持的虚拟文档和超过 200 万字符的文件跳过查询。Git 查询包含取消和缓存机制。

## 工具窗口

- **仓库**：列出内置 Git 扩展已发现的仓库，支持多仓库；展开查看当前分支、上游跟踪及 ahead/behind、已暂存、未暂存/未跟踪、合并冲突和最近提交 SHA。
- **Commit**：默认展开，上方为平铺的 Changes 文件列表，文件名后显示相对目录，下方为提交信息与 Commit 按钮。修改文件名为蓝色，新增为绿色，未受版本控制的为红色。
- 复选框未选中时透明，选中/半选时填充蓝色。双击文件行（或聚焦后按 Enter）在编辑区打开带行复选框的 Git Diff，左右比较 HEAD 与当前工作区代码；新增/未跟踪文件与空内容对比，删除文件显示删除内容，重命名文件与原路径版本对比。
- **快捷操作**：打开源代码管理、刷新本地状态、打开 Git 设置和查看日志。
- 仓库和文件状态变化时自动更新；关闭仓库后移除对应监听。
- 空工作区、无仓库、Git 被禁用、未信任工作区和无提交仓库均有对应提示。仓库需要通过内置 Git 扩展发现；无法显示时可先打开源代码管理检查 Git 状态。
- 改动数量按各分组显示；同一文件同时有暂存和未暂存改动时会分别计入。点击改动分组会打开 VS Code 源代码管理。
- 当前设置按钮打开 VS Code 的 Git 设置；尚未提供未实现功能的配置项。

## Git Control

**Git Control** 位于 VS Code 底部面板，与 **Terminal / Output / Problems** 同级。点击底部 **Git Control** 标签即可打开；如果面板收起，按 **⌘J**（Windows/Linux：Ctrl+J）展开。

也可执行 **GitToolBox: Git Control** 命令，或点击左侧 Commit / 仓库标题栏的分支图标，直接展开并聚焦该面板。修改视图注册配置后，需停止当前调试并重新按 F5 启动开发宿主，加载新的底部入口。

- **分支**：左侧区分 Local 与 Remote，支持按名称筛选。点击分支筛选该分支的历史，“全部分支”查看所有本地已知分支的提交。选择非当前的本地分支后，可点击“切换到此分支”。切换使用正常 Git Checkout，遇到冲突保留本地改动并显示错误；远程分支支持查看历史。
- **提交记录**：中间显示彩色分支连线、分叉与合并节点，以及说明、作者、时间和 SHA；分支标签放在提交消息后面。连线按真实父提交关系绘制，超出已加载范围的父提交用虚线延续。按说明、作者或 SHA 搜索已加载记录；过滤时连线跨过被隐藏的提交。每次加载 50 条，最多加载 1000 条。
- **提交详情**：右侧上方按目录展示所选提交的修改文件，下方为完整说明、作者、时间和 SHA，两部分分别滚动。所有目录默认展开；没有直属改动文件且只有一个子目录的连续路径合并为 `src/main/` 形式，保留一级目录名，遇到文件或分叉停止合并。根目录文件直接显示。双击文件对比该提交与父提交；首个提交与空内容比较，合并提交与第一个父提交比较。工作区改动继续通过左侧 Commit 面板查看。
- 顶部支持切换仓库、刷新和跳转已有 Commit 面板。仓库状态变化后自动更新；空工作区、无提交仓库均有提示。
- 分支、提交记录和详情之间可拖动分隔线调整宽度，详情中的文件列表和提交信息之间可上下拖动。布局会保存；双击分隔线恢复默认尺寸。分隔线也支持键盘方向键调整，Shift 加速，Home / End 调到边界。窗口较窄时可水平滚动查看三栏。

## 提交改动

1. 在开发宿主窗口中按 **⌘K**（Windows/Linux：**Ctrl+K**），或执行 **GitToolBox: Commit Changes**，打开左侧 Commit 面板。
2. 多仓库时先选择仓库。在 **Changes** 下勾选整个文件，或双击文件打开 Diff，直接勾选改动行左侧的复选框。勾选即暂存该行，取消勾选即取消暂存；顶部复选框支持全选/取消全部。替换行左右两侧作为一项选择，无需先选择代码范围或执行右键命令。未跟踪文件放在 **Unversioned Files** 中，也可逐行勾选。
3. 在下方 **Commit Message** 输入提交信息，点击 **Commit**。未选文件或提交信息为空时按钮不可用。

文件仅选部分行时，Commit 面板同步显示蓝底 **-** 半选状态，提交只包含该文件已暂存的行；剩余改动留在工作区。全选框和分组框也会反映半选状态。点击半选框可改为整文件 **✓**，再次点击取消文件选择。Diff 中可直接取消行复选框；已有的暂存行也会显示为选中。

整文件和半选文件可以混合提交，其他未勾选文件的暂存状态保留。支持新增、修改、删除、重命名和首个提交。行复选框 Diff 为只读视图，展示已保存代码；需要编辑时可点击顶部 **原生 Diff**。二进制、不支持的编码、过大文件或暂存内容无法映射到当前改动时，视图提示使用原生 Diff，也可整文件提交。文件或暂存状态在操作期间发生变化时停止当前勾选并刷新。存在合并冲突时需先处理，合并/变基/拣选进行中不允许部分行提交。

提交失败时保留消息和选择，所选文件可能已进入暂存区，可修复问题后重试。每个仓库的草稿分别保存，成功提交后清空对应草稿。不自动保存编辑器中尚未保存的内容，不执行 Push。

**⌘K / Ctrl+K** 会作为单键提交入口占用 VS Code 同前缀的组合快捷键，可在“键盘快捷方式”中搜索 `gittoolbox.openCommit` 修改绑定；终端和快速选择窗口内不触发。

## 常用命令

| 命令 | 说明 |
| --- | --- |
| `npm run watch` | 开发构建，包含 source map，监听源码变化 |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm run lint` | ESLint 检查 |
| `npm run check` | 执行类型和代码检查 |
| `npm test` | 文件选择、提交语义及界面交互测试 |
| `npm run build` | 生产构建 |
| `npm run package` | 检查、测试、构建并生成 `artifacts/*.vsix` |

通过 VS Code 的 **Extensions: Install from VSIX...** 命令安装本地产物。`publisher: local-dev` 为本地开发占位值；正式发布前需设置自己的 Marketplace publisher、仓库地址和许可协议。当前包设置为 `private` 和 `UNLICENSED`，未配置自动发布。

## 项目结构

```text
src/extension.ts       扩展入口、命令注册和资源释放
src/git/types.ts       内置 Git API v1 的最小类型适配
src/views/             仓库树视图和快捷操作
src/commit/            提交面板及 Git 文件选择提交逻辑
src/blame/             当前行装饰、Git Blame 查询与解析
src/control/           Git Control 管理窗口、分支和历史读取
resources/             活动栏图标、Commit 界面脚本与样式
tests/                 临时 Git 仓库与界面交互测试
.vscode/               扩展宿主调试、构建任务和编辑器设置
.github/workflows/     持续集成：检查、构建、生成 VSIX
esbuild.mjs            开发与生产打包
eslint.config.mjs      代码检查规则
```

GitToolBox 的命令使用 `gittoolbox.*` 前缀。后续按功能提取模块，并通过 `ExtensionContext.subscriptions` 管理事件监听、装饰器及其他可释放资源。
